# Self Forge

Веб-приложение для силовых тренировок дома и на уличных площадках. Человек указывает своё
оборудование, цель и места, где тренируется, — приложение собирает программу на мезоцикл,
ведёт по ней на экране тренировки и обеспечивает прогрессию даже при фиксированном весе
снарядов.

Прод: https://selfforge.hexdevop.ru — после первого деплоя по [docs/07-deploy.md](docs/07-deploy.md).

## Возможности

- **Онбординг и уровень по паттернам движения.** Поведенческие вопросы вместо самооценки;
  уровень хранится отдельно для каждого из 10 паттернов (присед, наклон, жимы, тяги…).
- **Места и инвентарь.** Дом, площадка, поездка — у каждого места своё оборудование и
  ограничения (тихий режим, низкий потолок, покрытие). Сетка доступных весов и калькулятор
  блинов.
- **Программа на 4 недели** с объяснением, почему она такая: раскладка дней по местам,
  накопление объёма и разгрузочная неделя.
- **Шесть рычагов прогрессии**: повторы, вес, ступень лестницы, односторонний вариант, темп,
  плотность и объём — плюс откат после трёх неудачных тренировок подряд.
- **Экран тренировки** для телефона в руке: предзаполненные веса, таймер отдыха по метке
  времени, Wake Lock, звуковой сигнал, раздельный лог сторон, замена упражнения, «осталось
  меньше времени». Подходы сохраняются на устройстве и уходят на сервер пачками — связь может
  моргать, приложение можно свернуть.
- **Самочувствие перед стартом** масштабирует объём; свободная тренировка вне программы.
- **Прогресс**: серия недель, графики по паттернам, тоннаж, рекорды, календарь, дисбаланс
  сторон, дерево навыков, замеры тела со средним весом за 7 дней, фото со сравнением шторкой.
- **Погода**: для уличных дней — прогноз и предложение сделать ту же тренировку дома.
- **PWA**: установка на домашний экран, подсказка для iOS.
- **Экспорт всех данных** одним JSON-файлом.

## Структура репозитория

```
backend/          API на FastAPI
├── app/engine/   движок: программа, прогрессия, сессия, аналитика, погода — чистая логика
├── app/          api/v1 → services → repositories → models, schemas
├── alembic/      миграции
├── seed/         справочник упражнений, паттернов, оборудования, навыков (YAML)
└── tests/        pytest на настоящем PostgreSQL
frontend/         SPA на React
├── src/routes/   экраны (файловый роутинг TanStack Router)
├── src/features/ онбординг, инвентарь, программа, тренировка, прогресс, погода, …
└── src/api/      клиент и сгенерированные типы API
deploy/           прод-стек: docker-compose, конфиг nginx, скрипты деплоя и бэкапов
docs/             спецификации — источник истины по домену
```

## Быстрый старт

### Что нужно установить

- Docker с Compose v2 — PostgreSQL, Redis, MinIO и Mailpit для разработки;
- [uv](https://docs.astral.sh/uv/) — Python и зависимости бэкенда;
- Node.js 24 и corepack — pnpm нужной версии подтягивается сам (`corepack pnpm …`).

### Бэкенд

```bash
cd backend
cp .env.example .env              # значения для локального запуска уже подходят
docker compose up -d db redis minio mailpit
uv sync
make migrate                      # схема базы
make seed                         # справочник: 120 упражнений, 10 паттернов, навыки
make dev                          # http://localhost:8000, документация — /docs
```

Письма (подтверждение адреса, сброс пароля) ловит Mailpit: http://localhost:8025.
Консоль MinIO: http://localhost:9001.

### Фронтенд

```bash
cd frontend
corepack pnpm install
corepack pnpm dev                 # http://localhost:5173, /api проксируется на :8000
```

Дальше — зарегистрироваться, пройти онбординг, добавить места и собрать программу.

### Демо-данные вручную

Отдельного генератора демо-данных нет: быстрее всего пройти онбординг в интерфейсе. Для
прогноза погоды у уличного места должны быть координаты — кнопка «Я сейчас на этой
площадке» в разделе «Места».

## Тесты и CI

- Бэкенд тестируется на настоящем PostgreSQL (модель данных опирается на JSONB), Redis —
  `fakeredis`, внешние сервисы (прогноз, хранилище) подменяются. Нужен запущенный
  `docker compose up -d db`; база `app_test` создаётся сама.
- Движок покрыт табличными тестами плотнее всего остального: `backend/tests/engine/`.
- CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на каждый push и PR: бэкенд —
  ruff, mypy, pytest; фронтенд — lint, typecheck, test, build и проверка, что
  `src/api/schema.d.ts` совпадает со схемой бэкенда.

`/api/v1/openapi.json`. Контракт и соглашения (формат ошибок, веса строками, идемпотентность

## Деплой и бэкапы

Прод поднимается скриптом `deploy/deploy.sh` на VPS с уже работающим nginx; каталог проекта
на сервере — любой. Бэкапы базы и фото — `deploy/backup.sh` по cron, восстановление —
`deploy/restore.sh`. Пошагово: [docs/07-deploy.md](docs/07-deploy.md).

## Правила разработки

Коротко; полностью — в [CLAUDE.md](CLAUDE.md).

- Перед задачей — прочитать относящиеся к ней `docs/`; чего нет в спецификации — спросить.
- Работа вертикальными срезами: миграция → модель → сервис → эндпоинт → типы → экран.
- Движок (`backend/app/engine/`) не импортирует SQLAlchemy, FastAPI, Redis и покрыт тестами.
- Слои бэкенда: `api/v1 → services → repositories → models`, наружу — только схемы.
- Любое изменение модели — с миграцией; справочные данные — только через seed.
- Перед коммитом — `lint`, `typecheck`, `test` с обеих сторон. Коммиты — Conventional
  Commits на английском.
- Тексты интерфейса — на русском, на «ты»; без стыда за пропуски и без обещаний сроков.
