# Движок

Живёт в `backend/app/engine/`. Не импортирует SQLAlchemy, FastAPI, Redis. Вход и выход —
структуры данных. Каждая функция чистая и детерминированная. Это ядро ценности продукта,
и оно покрывается табличными тестами плотнее всего остального кода.

```
app/engine/
├── types.py         входные структуры: место, оборудование, упражнение справочника
├── inventory.py     что можно сделать этим инвентарём, сетка весов, блины
├── assessment.py    поведенческие ответы онбординга → уровни по паттернам
├── patterns.py      лестницы сложности, главная линия
├── goals.py         схемы подходов и порядок рычагов по целям
├── progression.py   шесть рычагов, откат
├── mesocycle.py     программа на 4 недели, свободная тренировка на один день
├── session.py       подготовка тренировки, замена, сокращение, перенос в другое место
├── analytics.py     1ПМ, тоннаж, среднее веса, серия, дисбаланс, навыки
├── weather.py       решение «тренироваться ли на улице» по прогнозу
└── text.py          русские формулировки: склонения, килограммы, минуты
```

Всё, что уходит к пользователю, движок формулирует сам (`hint_ru`, `notes_ru`,
`rationale_ru`, `text_ru`): объяснение рождается там же, где решение.

## 1. Разрешение инвентаря

`resolve_available_exercises(locations, health_flags, catalog) -> dict[LocationId, list[Exercise]]`

Фильтрует каталог по каждой локации. Учитывает:
- наличие оборудования (`required_equipment` поддерживает «или»: турник **или** петли)
- количество снарядов — `requires_pair` против `quantity == 1`
- ограничения локации: `quiet_mode` отсекает `is_quiet == false`, `low_ceiling` отсекает
  жим над головой стоя, `limited_space` отсекает упражнения с перемещением
- покрытие площадки: песок и асфальт отсекают упражнения лёжа
- теги здоровья — `contraindicated_for`

`weight_grid(equipment) -> list[Decimal]`
Из грифа и блинов считает все достижимые веса. Для фиксированных гантель — просто список.
Возвращает отсортированный набор; движок никогда не предлагает вес вне сетки.

`plate_breakdown(target_kg, equipment) -> list[Plate] | None`
Для калькулятора блинов.

## 2. Шесть рычагов прогрессии

Порядок применения зависит от цели и от того, упёрся ли человек в потолок железа.

1. **Повторы** — двойная прогрессия. Диапазон задан целью (например 8–12). Набрал верхнюю
   границу во всех подходах → добавляем вес, откатываемся к нижней границе.
2. **Вес** — только если сетка позволяет. Шаг = минимальный доступный по сетке.
3. **Сложность движения** — следующая ступень лестницы паттерна. Применяется, когда вес
   добавить нельзя, а верхняя граница повторов взята.
4. **Односторонность** — переход с двустороннего варианта на односторонний фактически
   удваивает нагрузку без нового железа.
5. **Темп и паузы** — медленное опускание, пауза в нижней точке (реализовано два шага,
   см. ниже; полуторные и частичные повторы — пока нет).
6. **Плотность и объём** — сокращение отдыха при том же объёме; добавление подхода.

Дополнительно для дома: **внешний груз** (рюкзак, жилет) и **резинка** как аккомодирующее
сопротивление — она же работает в минус для подтягиваний и брусьев у новичков.

```
next_progression(history, goal, location, catalog, health_flags) -> ProgressionDecision
```

`history` — выполнения одной ячейки плана, от старых к новым; решение строится от последнего.

`ProgressionDecision` содержит: рычаг, новые параметры подхода, человекочитаемое объяснение
на русском (показывается пользователю на уровнях verbose и normal).

Порядок рычагов после взятого верха диапазона (схемы целей — `engine/goals.py`):

| Цели | Порядок |
|---|---|
| `strength`, `hypertrophy`, `health`, `maintenance` | вес → ступень → односторонний вариант → темп → +подход |
| `endurance`, `fat_loss` | вес → меньше отдыха → +подход → ступень → темп |
| `skill` | ступень → темп (вес и объём не растут) |

Темп идёт в два шага: медленное опускание 3 секунды, затем пауза 2 секунды внизу. Когда все
рычаги исчерпаны — «потолок»: результат держится до пересборки программы.

## 3. Откат и дедлоад

**Правило отката.** Три тренировки подряд не добираешь нижнюю границу диапазона повторов →
минус 10% веса, либо шаг назад по лестнице сложности, если вес снизить нельзя. Тренировка
не добрана, если повторов в среднем по подходам меньше нижней границы; вес −10% округляется
до ближайшего существующего в сетке.

**Дедлоад.** Последняя неделя мезоцикла — `volume_multiplier` около 0.5–0.6 при сохранении
интенсивности. Не пропуск тренировок, а снижение объёма.

**Авторегуляция.** Перед сессией три тапа: сон, стресс, крепатура — каждый `bad` / `ok` /
`good` (1–3 балла). Сумма баллов задаёт множитель объёма:

| Баллы | 3 | 4 | 5 | 6 (всё «обычно») | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|
| Объём | 0.7 | 0.8 | 0.9 | 1.0 | 1.05 | 1.1 | 1.1 |

Масштабируется общее число подходов тренировки, а не каждое упражнение отдельно:
поупражненческое округление оставляло день на 1.05 без изменений, а день на 0.9 резало
дважды. Ниже единицы первым уходит финишер, затем подходы вспомогательных упражнений
(не ниже одного); основные движения не теряют ни подхода. Выше единицы лишние подходы
добавляются сначала вспомогательным, в пределах `max_sets` цели.

## 4. Сборка мезоцикла

```
build_mesocycle(inp: ProgramInput, locations, catalog, equipment_titles) -> Program
build_one_off_day(inp: ProgramInput, location, catalog) -> PlannedDay
```

`build_one_off_day` — свободная тренировка вне программы: один фулбоди-день для одного места
по тем же правилам подбора.

Шаги:
1. Выбрать структуру по числу дней (см. `01-domain.md`), с поправкой на распределение
   локаций по дням.
2. Разложить паттерны по дням так, чтобы за неделю сошёлся целевой объём на каждую
   мышечную группу. Уличные дни забирают `pull_v`, `pull_h`, `push_h` на брусьях; домашние
   дни — `squat`, `hinge`, `lunge` с железом.
3. Для каждого паттерна выбрать упражнение по `pattern_levels` и доступному инвентарю.
4. Назначить схемы подходов из профиля цели.
5. Разложить недели: накопление объёма, затем дедлоад.
6. Сгенерировать `rationale_ru` — объяснение, почему структура такая. Обязательно, если
   она отличается от ожидаемой (например, фулбоди превратился в гибрид из-за площадки).

Как это устроено сейчас:
- Место каждого дня выбирает человек на экране предпросмотра. Шаблоны дней (верх / низ,
  жим / тяга / ноги) раздаются дням так, чтобы место лучше всего подходило шаблону; внутри
  дня вперёд идут паттерны, для которых это место лучше других мест недели, назад — те, для
  которых лучше другое. Паттерн, не попавший ни в один шаблон, получает слот там, где для него
  лучшее оборудование.
- Упражнение — самая сложная ступень не выше уровня паттерна (на одну выше, если ниже ничего
  нет); при равенстве — со снарядом, на повторы, двустороннее, с главной линии лестницы.
- Первые два базовых упражнения дня — основные (схема основной цели), остальные —
  вспомогательные (схема второстепенной цели, если она есть). Финишер — при цели
  `fat_loss`/`endurance` основной или второстепенной.
- 4 недели: объём 1.0 → 1.1 → 1.2, затем дедлоад 0.6. Лишние подходы добавляются, только пока
  тренировка укладывается в `session_minutes`; упражнения одни и те же все четыре недели.
- `strength` без штанги — честное предупреждение в `rationale_ru`.

Программа не пересобирается автоматически при каждом изменении. Сейчас пересборка — только
по явному запросу: человек собирает программу заново (`POST /programs`), прежняя становится
`abandoned`. Автоматическое предложение пересобрать по завершении мезоцикла или после
существенного изменения инвентаря пока не сделано.

## 5. Работа с сессией

```
prepare_session(planned, history, readiness, location, catalog, goal, health_flags) -> Session
```
Превращает день плана в тренировку с конкретными весами:
- **История по ячейке плана.** `history` — что на самом деле делалось в каждой ячейке плана
  (`planned_slug`), от старых к новым. Рычаг сложности может перевести ячейку на другое
  упражнение, а план сохраняет исходный slug — прогрессия идёт по ячейке и не теряется.
  Выполнения упражнений, которые нельзя сделать в этом месте (ячейка делалась дома в дождь),
  прогрессию здесь не ведут.
- **Первый раз** — самый лёгкий вес сетки и нижняя граница диапазона.
- **Авторегуляция** — см. §3.
- **Разминка** — общая часть и по одному упражнению на каждый паттерн дня, в пределах минут
  блока; **заминка** — дыхание и растяжка.
- **Под место.** В конце вызывается `swap_location` для места, где тренировка идёт на самом
  деле: день площадки, начатый дома, получает домашние упражнения.

```
substitute_exercise(current, reason, location, catalog, goal, used, health_flags) -> SessionExercise | None
```
Замена того же паттерна из доступного **здесь и сейчас**, не из уже стоящих в тренировке.
`too_hard` — ступень ниже, `too_easy` — выше, `equipment_busy` — в первую очередь без того же
оборудования, `pain` и `disliked` — ближайшая по сложности. Вес — не тяжелее прежнего из
сетки. Причина пишется в `substitutions` тренировки: повторяющиеся отказы — сигнал
скорректировать программу. Текст при боли не даёт медицинских советов.

```
trim_session(session, minutes_left) -> Session
```
Пересборка под оставшееся время, с пересчётом минут после каждого шага (минуты блока
округляются вверх). Порядок: финишер и вспомогательные с конца → заминка → подходы основных
движений (не ниже одного). Разминка не режется никогда, основное движение не удаляется.

```
swap_location(session, location, catalog, goal, health_flags, done) -> Session
```
Та же тренировка в другом месте: те же паттерны, другие снаряды. Что место позволяет —
остаётся (вес подгоняется под сетку); остальное — ближайшая по сложности ступень того же
паттерна, при равенстве лёгкая. Упражнения из `done` (по ним уже есть подходы) не трогаются.
Если паттерн здесь сделать нечем, упражнение выпадает, а `notes_ru` называет, что сегодня
без него. Причина замен — `weather`.

## 6. Симметрия при односторонней работе

Жёсткое правило: одинаковое число повторов на обе стороны. Если слабая сторона сделала
меньше — сильная равняется на неё, а не догоняет. Дисбаланс больше 15% по среднему за
4 недели подсвечивается пользователю с предложением добавить объём на отстающую сторону.

## 7. Аналитика

- **Расчётный 1ПМ** — формула Эпли: `1RM = weight * (1 + reps / 30)`. Считается только до
  10 повторов включительно; дальше формула врёт, и результат не показывается.
- **Тоннаж** — `(внешний вес + bodyweight_share × масса тела) × повторы` по рабочим
  подходам. Коэффициент задан на упражнение в справочнике: он ненулевой везде, где
  двигается само тело — отжимания, подтягивания, приседы и выпады, в том числе с гирей, —
  чтобы тоннаж не проседал при переходе по лестнице. Масса тела — последнее взвешивание до
  тренировки; без взвешиваний учитывается только внешний вес. Упражнения на время и разминка
  в тоннаж не входят.
- **Среднее веса за 7 дней** — по точке на каждый день со взвешиванием; сырые значения как
  основной график не показываются.
- **Серия** — недели подряд хотя бы с одной тренировкой. Текущая неделя, в которой ещё не
  было тренировки, серию не рвёт. Неделя — с понедельника, в часовом поясе человека.
- **Лучший результат** — по рабочим подходам: расчётный 1ПМ, если был вес, иначе повторы или
  секунды. Односторонний подход засчитывается по слабой стороне и только когда записаны обе.
- **Прогресс по паттерну** — точка на тренировку: самая сложная сделанная ступень и её
  лучший подход. При смене ступени история не рвётся; линия лучшего подхода на экране
  показывает текущую ступень, потому что повторы лёгкого и тяжёлого варианта несравнимы.
- **Рекорд рядом** — последний результат упражнения не ниже 90% лучшего прежнего.
- **Дисбаланс сторон** — см. §6.
- **Навыки.** `locked`, пока не выполнены предусловия; `in_progress` после; `achieved`, когда
  лучший подход достиг цели навыка (`skills.goal`) или человек отметил навык сам (у навыков
  без своего упражнения в справочнике цели нет). Освоенный навык остаётся освоенным; дата —
  первая тренировка, где цель выполнена. `current_lead_up` — подводящее упражнение, которое
  делалось последним.

## 8. Погода

```
assess(hours, start, minutes) -> Verdict | None
```
Смотрит на часы прогноза, пересекающиеся с окном `[start, start + max(minutes, 3 ч)]`; окно —
длина тренировки плюс дорога туда и обратно. `None`, если прогноз окно не покрывает.

| Что | Порог | Итог |
|---|---|---|
| Дождь или снег | осадки ≥ 0,5 мм/ч или вероятность ≥ 60% в любой час окна | предложить дом |
| Ветер | порывы ≥ 15 м/с | предложить дом |
| Холод | по ощущению ≤ −15 °C | предложить дом |
| Жара | по ощущению ≥ +32 °C | предложить дом |
| Минус | по ощущению < 0 °C | совет: разминка дома, меньше статики |
| Тепло | по ощущению ≥ +27 °C | совет: утром или вечером, взять воду |

Снег от дождя отличается по коду погоды WMO у большинства «мокрых» часов. Решение —
предложение, не запрет: тренировка на улице остаётся доступной. Перенос — `swap_location`.

## Тестирование

Табличные тесты на сценариях. Обязательный минимум:

- одна гиря 16 кг + цель `strength` + 3 дня + только дом
- одна гантель 10 кг + цель `hypertrophy` + новичок с нулём подтягиваний
- пара гантель фиксированных 16 кг, потолок прогрессии → переход на лестницу сложности
- разборные гантели с нестандартным набором блинов → проверка сетки весов
- 4 дня, два из них площадка → проверка перераспределения паттернов и наличия `rationale_ru`
- `quiet_mode` включён → в программе нет прыжков, скакалки, бросков
- `low_ceiling` → нет жима над головой стоя
- три неудачные тренировки подряд → сработал откат
- дисбаланс сторон 20% → подсветка
- цель `strength` при заведомо недостаточном железе → честное предупреждение в `rationale_ru`
- ограничение по колену → `squat` подобран из безопасных вариантов
- осталось 15 минут → основные движения сохранены, изоляция срезана
- день площадки перенесён домой → те же паттерны, всё доступно дома, пропущенное названо
- дождь, ветер, холод, жара на границах порогов → предложение переноса; мягкие советы

Тесты лежат в `backend/tests/engine/` и работают на настоящем справочнике из `seed/`.
