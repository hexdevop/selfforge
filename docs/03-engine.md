# Движок

Живёт в `backend/app/engine/`. Не импортирует SQLAlchemy, FastAPI, Redis. Вход и выход —
структуры данных. Каждая функция чистая и детерминированная. Это ядро ценности продукта,
и оно покрывается табличными тестами плотнее всего остального кода.

```
app/engine/
├── types.py         входные и выходные структуры
├── inventory.py     что можно сделать этим инвентарём, сетка весов
├── patterns.py      лестницы сложности, переходы между ступенями
├── progression.py   шесть рычагов, дедлоад, откат
├── mesocycle.py     сборка программы на 4–6 недель
├── session.py       подбор весов, замена упражнения, урезание по времени
└── analytics.py     1ПМ, тоннаж, дисбаланс сторон
```

## 1. Разрешение инвентаря

`resolve_available_exercises(locations, health_flags, catalog) -> dict[LocationId, list[Exercise]]`

Фильтрует каталог по каждой локации. Учитывает:
- наличие оборудования (`required_equipment` поддерживает «или»: турник **или** петли)
- количество снарядов — `requires_pair` против `quantity == 1`
- ограничения локации: `quiet_mode` отсекает `is_quiet == false`, `low_ceiling` отсекает
  жим над головой стоя, `limited_space` отсекает упражнения с перемещением
- покрытие площадки: песок и асфальт отсекают упражнения лёжа
- теги здоровья — `contraindicated_for`

`weight_grid(equipment) -> list[Decimal]`
Из грифа и блинов считает все достижимые веса. Для фиксированных гантель — просто список.
Возвращает отсортированный набор; движок никогда не предлагает вес вне сетки.

`plate_breakdown(target_kg, equipment) -> list[Plate] | None`
Для калькулятора блинов.

## 2. Шесть рычагов прогрессии

Порядок применения зависит от цели и от того, упёрся ли человек в потолок железа.

1. **Повторы** — двойная прогрессия. Диапазон задан целью (например 8–12). Набрал верхнюю
   границу во всех подходах → добавляем вес, откатываемся к нижней границе.
2. **Вес** — только если сетка позволяет. Шаг = минимальный доступный по сетке.
3. **Сложность движения** — следующая ступень лестницы паттерна. Применяется, когда вес
   добавить нельзя, а верхняя граница повторов взята.
4. **Односторонность** — переход с двустороннего варианта на односторонний фактически
   удваивает нагрузку без нового железа.
5. **Темп и паузы** — эксцентрика 3–4 секунды, пауза 2 секунды в нижней точке, полуторные
   повторы, частичные в конце подхода.
6. **Плотность и объём** — сокращение отдыха при том же объёме; добавление подхода.

Дополнительно для дома: **внешний груз** (рюкзак, жилет) и **резинка** как аккомодирующее
сопротивление — она же работает в минус для подтягиваний и брусьев у новичков.

```
next_progression(
    exercise, history, goal, inventory, pattern_level
) -> ProgressionDecision
```

`ProgressionDecision` содержит: рычаг, новые параметры подхода, человекочитаемое объяснение
на русском (показывается пользователю на уровнях verbose и normal).

Порядок рычагов после взятого верха диапазона (схемы целей — `engine/goals.py`):

| Цели | Порядок |
|---|---|
| `strength`, `hypertrophy`, `health`, `maintenance` | вес → ступень → односторонний вариант → темп → +подход |
| `endurance`, `fat_loss` | вес → меньше отдыха → +подход → ступень → темп |
| `skill` | ступень → темп (вес и объём не растут) |

Темп идёт в два шага: медленное опускание 3 секунды, затем пауза 2 секунды внизу. Когда все
рычаги исчерпаны — «потолок»: результат держится до пересборки программы.

## 3. Откат и дедлоад

**Правило отката.** Три тренировки подряд не добираешь нижнюю границу диапазона повторов →
минус 10% веса, либо шаг назад по лестнице сложности, если вес снизить нельзя. Тренировка
не добрана, если повторов в среднем по подходам меньше нижней границы; вес −10% округляется
до ближайшего существующего в сетке.

**Дедлоад.** Последняя неделя мезоцикла — `volume_multiplier` около 0.5–0.6 при сохранении
интенсивности. Не пропуск тренировок, а снижение объёма.

**Авторегуляция.** Перед сессией три тапа: сон, стресс, крепатура. Суммарная готовность
масштабирует объём в диапазоне примерно 0.7–1.1. При низкой готовности срезаются
вспомогательные блоки, основные движения сохраняются.

## 4. Сборка мезоцикла

```
build_mesocycle(profile, pattern_levels, locations, history) -> Program
```

Шаги:
1. Выбрать структуру по числу дней (см. `01-domain.md`), с поправкой на распределение
   локаций по дням.
2. Разложить паттерны по дням так, чтобы за неделю сошёлся целевой объём на каждую
   мышечную группу. Уличные дни забирают `pull_v`, `pull_h`, `push_h` на брусьях; домашние
   дни — `squat`, `hinge`, `lunge` с железом.
3. Для каждого паттерна выбрать упражнение по `pattern_levels` и доступному инвентарю.
4. Назначить схемы подходов из профиля цели.
5. Разложить недели: накопление объёма, затем дедлоад.
6. Сгенерировать `rationale_ru` — объяснение, почему структура такая. Обязательно, если
   она отличается от ожидаемой (например, фулбоди превратился в гибрид из-за площадки).

Как это устроено сейчас:
- Место каждого дня выбирает человек на экране предпросмотра. Шаблоны дней (верх / низ,
  жим / тяга / ноги) раздаются дням так, чтобы место лучше всего подходило шаблону; внутри
  дня вперёд идут паттерны, для которых это место лучше других мест недели, назад — те, для
  которых лучше другое. Паттерн, не попавший ни в один шаблон, получает слот там, где для него
  лучшее оборудование.
- Упражнение — самая сложная ступень не выше уровня паттерна (на одну выше, если ниже ничего
  нет); при равенстве — со снарядом, на повторы, двустороннее, с главной линии лестницы.
- Первые два базовых упражнения дня — основные (схема основной цели), остальные —
  вспомогательные (схема второстепенной цели, если она есть). Финишер — при цели
  `fat_loss`/`endurance` основной или второстепенной.
- 4 недели: объём 1.0 → 1.1 → 1.2, затем дедлоад 0.6. Лишние подходы добавляются, только пока
  тренировка укладывается в `session_minutes`; упражнения одни и те же все четыре недели.
- `strength` без штанги — честное предупреждение в `rationale_ru`.

Программа не пересобирается автоматически при каждом изменении. Пересборка происходит:
по завершении мезоцикла, при существенном изменении инвентаря, по явному запросу
пользователя.

## 5. Работа с сессией

```
prepare_session(planned, history, readiness, location) -> Session
```
Подставляет веса из истории с учётом прогрессии, применяет авторегуляцию, добавляет
разминку под паттерны конкретного дня и заминку.

```
substitute_exercise(exercise, reason, available, session) -> Exercise
```
Подбирает замену того же паттерна и близкой ступени сложности из доступного **здесь и
сейчас**. Причины: `equipment_busy` (занят турник — на площадке это постоянная история),
`pain`, `too_hard`, `too_easy`, `disliked`. Причина логируется: повторяющиеся отказы от
упражнения — сигнал скорректировать программу.

```
trim_session(session, minutes_left) -> Session
```
Пересборка остатка под оставшееся время. Приоритет: основные движения сохраняются,
вспомогательные и изоляция режутся первыми, разминка не режется никогда.

```
swap_location(session, from_location, to_location) -> Session
```
Погодная подмена: та же сессия, те же паттерны, другие снаряды.

## 6. Симметрия при односторонней работе

Жёсткое правило: одинаковое число повторов на обе стороны. Если слабая сторона сделала
меньше — сильная равняется на неё, а не догоняет. Дисбаланс больше 15% по среднему за
4 недели подсвечивается пользователю с предложением добавить объём на отстающую сторону.

## 7. Аналитика

- **Расчётный 1ПМ** — формула Эпли: `1RM = weight * (1 + reps / 30)`. Применима до ~10
  повторов, дальше врёт — за этой границей не показываем.
- **Тоннаж** — сумма `weight * reps` по сессии, неделе, паттерну. Для упражнений с весом
  тела в тоннаж входит доля массы тела (коэффициент на упражнение).
- **Скользящее среднее веса** за 7 дней — основной график массы тела. Сырые суточные
  значения не подаются как основной показатель.
- **Прогресс по паттернам, а не по упражнениям** — при смене ступени история не рвётся.

## Тестирование

Табличные тесты на сценариях. Обязательный минимум:

- одна гиря 16 кг + цель `strength` + 3 дня + только дом
- одна гантель 10 кг + цель `hypertrophy` + новичок с нулём подтягиваний
- пара гантель фиксированных 16 кг, потолок прогрессии → переход на лестницу сложности
- разборные гантели с нестандартным набором блинов → проверка сетки весов
- 4 дня, два из них площадка → проверка перераспределения паттернов и наличия `rationale_ru`
- `quiet_mode` включён → в программе нет прыжков, скакалки, бросков
- `low_ceiling` → нет жима над головой стоя
- три неудачные тренировки подряд → сработал откат
- дисбаланс сторон 20% → подсветка
- цель `strength` при заведомо недостаточном железе → честное предупреждение в `rationale_ru`
- ограничение по колену → `squat` подобран из безопасных вариантов
- осталось 15 минут → основные движения сохранены, изоляция срезана
