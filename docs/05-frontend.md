Pydantic — `pnpm gen:api` — TypeScript сразу показывает все сломанные места.

## Структура

```
frontend/src/
├── api/              сгенерированные типы, клиент, хуки TanStack Query
├── app/              роутер, провайдеры, layout
├── routes/           экраны (файловая структура TanStack Router)
├── features/
│   ├── onboarding/
│   ├── inventory/
│   ├── program/
│   ├── workout/      экран тренировки — самая сложная часть
│   ├── progress/
│   └── profile/
├── components/ui/    shadcn
├── components/       общие компоненты продукта
├── hooks/            useWakeLock, useRestTimer, useSetBuffer
├── lib/              утилиты, форматирование весов и времени

```

Правило: `features/*` не импортируют друг друга напрямую. Общее поднимается в
`components/` или `lib/`.

## Дизайн-система

### Направление

Продукт про железо, а не про фитнес-глянец. Отсюда два решения, которые задают всё
остальное.

**Светлая тема по умолчанию, тёмная опцией.** Причина не эстетическая: приложением
пользуются на улице при ярком солнце, где тёмная тема нечитаема. Это функциональное
требование, а не вкус.

**Смелость тратится в одном месте** — на активный подход и на момент прогрессии. Всё
остальное дисциплинированно-серое. Когда человек берёт новый вес или новую ступень —
интерфейс это отмечает, и это единственное яркое событие на экране.

### Палитра

База — холодный стальной серый, не бежевый и не кремовый.

```
--ink        #14181D   основной текст
--steel-700  #454E59   вторичный текст
--steel-400  #8E98A3   подписи, неактивное
--steel-200  #D2D7DC   границы
--steel-050  #EDEFF1   фон
--paper      #F8F9FA   поверхности
--heat       #E0532B   активный подход, новый рекорд, прогрессия
```

Тёмная тема — инверсия по той же шкале, `--heat` не меняется.

Отдельно — **функциональная палитра блинов**, повторяющая международную цветовую
маркировку дисков. Она используется в калькуляторе блинов и в чипах весов, то есть несёт
информацию, а не украшает:

```
25 кг #C8102E   20 кг #0057B8   15 кг #FFB81C
10 кг #00843D    5 кг #E9E9E9  2.5 кг #C8102E
```

### Типографика

Одна гарнитура — **Golos Text**. Кириллица родная, характер сдержанно-индустриальный, это
не дефолтный Inter. Никакого моноширинного шрифта для мелких подписей: там, где нужны
ровные колонки цифр, включается `font-variant-numeric: tabular-nums`.

Герой типографики — **числа**. Вес, повторы, таймер. Они набираются крупно и тяжело,
и именно они несут визуальную индивидуальность:

```
вес и таймер     56–72px, вес 700, tabular-nums
заголовок экрана 24px / 600
название упражн. 18px / 600
основной текст   16px / 400
подпись          13px / 400, --steel-400
```

Длина строки в текстах техники — до 70 символов.

### Чего не делаем

Не набираем подписи капслоком. Не выделяем одно слово в заголовке цветом. Не ставим
типографические ярлыки над каждым блоком. Не режем интерфейс на одинаковые скруглённые
карточки с одинаковой мягкой тенью. Не добавляем «→» в текст кнопок. Не используем
градиенты как украшение. Анимация появления блоков при скролле — не используется вообще;
движение только как ответ на действие пользователя.

Скругления разные по иерархии: крупные поверхности 12px, кнопки и чипы 8px, поля 6px.
Тени почти не используются — разделение через фон и границы.

## Экран тренировки

Самый важный экран продукта. Требования жёсткие, потому что им пользуются вспотевшей
рукой, с пола, одной рукой, иногда в перчатках, иногда на солнце.

```
┌─────────────────────────────────────┐
│ Жим гантелей лёжа        2 из 5     │  паттерн, позиция в сессии
├─────────────────────────────────────┤
│                                     │
│     16.0        ×        10         │  крупно, tabular-nums
│      кг                повторов     │  тап по числу → правка
│                                     │
│  ┌───────────────────────────────┐  │
│  │      Подход выполнен          │  │  основное действие, высота ≥56px
│  └───────────────────────────────┘  │
│                                     │
│  ✓ 16.0 × 10     ✓ 16.0 × 10        │  сделанные подходы
│  ○ подход 3      ○ подход 4         │
├─────────────────────────────────────┤
│  Отдых 1:28                         │  стартует сам, счёт от метки времени
├─────────────────────────────────────┤
│  Техника   Заменить   Осталось 15м  │
└─────────────────────────────────────┘
```

**Обязательное поведение:**

- Вес и повторы **предзаполнены** из прошлой тренировки с учётом прогрессии. Идеальный
  случай — подтверждение подхода в один тап, без ввода вообще.
- Таймер отдыха стартует автоматически после подтверждения подхода.
- **Таймер никогда не считает тики.** Хранится метка времени старта, оставшееся
  вычисляется как разница с текущим моментом. Иначе при сворачивании приложения на iOS
  таймер замерзает и показывает неправду.
- Экран не гаснет — Wake Lock API, с корректным переполучением блокировки после
  возврата из фона.
- Сигнал окончания отдыха — **звук через Web Audio**. Вибрация на iOS Safari не работает,
  на неё полагаться нельзя.
- Гифка техники разворачивается прямо здесь, не уводя с экрана.
- «Заменить» → альтернатива того же паттерна из доступного здесь и сейчас, с выбором
  причины.
- «Осталось 15 минут» → пересборка остатка сессии.
- Для односторонних упражнений — **раздельный лог левой и правой стороны**, с правилом
  симметрии.
- Уровень подсказок `verbose` даёт одно упражнение на экране с чек-листом техники;
  `quiet` — всю сессию списком с возможностью логировать не по порядку.

**Буфер подходов и устойчивость к связи.** Подтверждённый подход сразу попадает в Zustand
и отрисовывается — никаких спиннеров. Параллельно он кладётся в очередь и уходит на сервер
батчем с `client_uuid`, с экспоненциальными ретраями. Индикатор синхронизации показывается
только если очередь не уходит дольше ~30 секунд. При закрытии вкладки с непустой очередью —
предупреждение. Это не local-first, это защита от моргающей связи, но реализовать её надо
с первого дня экрана тренировки.

## PWA

Манифест, иконки, `display: standalone`, тема под цвет фона. На iOS установка только
через Safari → «Поделиться» → «На экран Домой»; в приложении должна быть короткая
подсказка, как это сделать, потому что сам iOS её не предлагает.

Service worker кеширует оболочку приложения и медиа упражнений. Данные пользователя
через service worker не кешируются — этим занимается TanStack Query.

## Доступность и качество

Видимый фокус на всех интерактивных элементах. Минимальная область нажатия 44×44.
Контраст текста не ниже 4.5:1. `prefers-reduced-motion` уважается. Все формы работают
с клавиатуры. Интерфейс не ломается при системном увеличении шрифта.

## Тексты интерфейса

Русский, обращение на «ты», предложениями в обычном регистре. Кнопка называет действие:
«Начать тренировку», а не «Старт». Название действия не меняется по ходу сценария.

Ошибки объясняют, что случилось и что делать, без извинений и без размытых формулировок.
Пустые экраны — приглашение к действию, а не констатация пустоты. Формулировок,
играющих на чувстве вины за пропуски, нет нигде.
