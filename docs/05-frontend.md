## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Основа | React 19 + TypeScript (strict) | — |
| Сборка | Vite | — |
| Пакеты | pnpm | — |
| Роутинг | TanStack Router | типобезопасные маршруты и параметры, файловая структура, SPA без лишней SSR-обвязки |
| Серверное состояние | TanStack Query | кеш, ретраи, инвалидация, фоновое обновление |
| Локальное состояние | Zustand | состояние активной тренировки, буфер подходов |

| Стили | Tailwind CSS v4 | — |
| Компоненты | shadcn/ui | код в репозитории, можно перекрашивать под свою систему |
| Формы | React Hook Form + Zod | онбординг — это длинная многошаговая форма |
| Графики | Recharts | — |
| Иконки | lucide-react | — |
| Анимация | — | отдельной библиотеки нет: движение только как ответ на действие, `prefers-reduced-motion` гасит всё |
| PWA | vite-plugin-pwa + workbox-window | манифест, service worker оболочки, обновление по тапу |
| Даты и числа | `Intl` | локаль ru без отдельной библиотеки |
| Линт и формат | Biome | один инструмент вместо ESLint + Prettier, симметрично ruff на бэке |
| Тесты | Vitest + Testing Library | e2e на Playwright — позже |

Зачем `openapi-typescript`: бэкенд и фронт не расходятся по типам вообще. Изменил схему в
Pydantic — `pnpm gen:api` — TypeScript сразу показывает все сломанные места.

## Структура

```
frontend/src/
├── api/              клиент (openapi-fetch), сгенерированные типы, запросы по разделам
├── routes/           экраны — файловая структура TanStack Router
│   ├── __root.tsx        корень, подсказка о новой версии
│   ├── login, register, …  вход, регистрация, подтверждение адреса, сброс пароля
│   └── _authed/          всё, что требует входа: кабинет, онбординг, места, упражнения,
│                         программа, тренировка, прогресс, навыки, тело
├── features/
│   ├── app/          установка PWA, обновление, выгрузка данных
│   ├── auth/
│   ├── catalog/      каталог упражнений и фильтры
│   ├── onboarding/
│   ├── inventory/    места, инвентарь, калькулятор блинов
│   ├── program/      предпросмотр, календарь мезоцикла, карточка дня
│   ├── workout/      экран тренировки — самая сложная часть
│   ├── progress/     графики и форматирование прогресса
│   └── weather/      прогноз, отметка площадки
├── components/ui/    shadcn
├── components/       общие компоненты продукта (ChoiceGroup, поля форм)
└── lib/              утилиты, форматирование весов и склонений
```

`src/api/schema.d.ts` и `src/routeTree.gen.ts` генерируются и коммитятся, руками не
правятся.

Правило: `features/*` не импортируют друг друга напрямую. Общее поднимается в
`components/` или `lib/`. Единственное исключение — `features/weather`: блок прогноза и
кнопку отметки площадки встраивают `features/workout` и `features/inventory`.

## Дизайн-система

### Направление

Продукт про железо, а не про фитнес-глянец. Отсюда два решения, которые задают всё
остальное.

**Светлая тема по умолчанию, тёмная опцией.** Причина не эстетическая: приложением
пользуются на улице при ярком солнце, где тёмная тема нечитаема. Это функциональное
требование, а не вкус.

**Смелость тратится в одном месте** — на активный подход и на момент прогрессии. Всё
остальное дисциплинированно-серое. Когда человек берёт новый вес или новую ступень —
интерфейс это отмечает, и это единственное яркое событие на экране.

### Палитра

База — холодный стальной серый, не бежевый и не кремовый.

```
--ink        #14181D   основной текст
--steel-700  #454E59   вторичный текст
--steel-400  #8E98A3   подписи, неактивное
--steel-200  #D2D7DC   границы
--steel-050  #EDEFF1   фон
--paper      #F8F9FA   поверхности
--heat       #E0532B   активный подход, новый рекорд, прогрессия
```

Тёмная тема — инверсия по той же шкале, `--heat` не меняется.

Отдельно — **функциональная палитра блинов**, повторяющая международную цветовую
маркировку дисков. Она используется в калькуляторе блинов и в чипах весов, то есть несёт
информацию, а не украшает:

```
25 кг #C8102E   20 кг #0057B8   15 кг #FFB81C
10 кг #00843D    5 кг #E9E9E9  2.5 кг #C8102E
```

### Типографика

Одна гарнитура — **Golos Text**. Кириллица родная, характер сдержанно-индустриальный, это
не дефолтный Inter. Никакого моноширинного шрифта для мелких подписей: там, где нужны
ровные колонки цифр, включается `font-variant-numeric: tabular-nums`.

Герой типографики — **числа**. Вес, повторы, таймер. Они набираются крупно и тяжело,
и именно они несут визуальную индивидуальность:

```
вес и таймер     56–72px, вес 700, tabular-nums
заголовок экрана 24px / 600
название упражн. 18px / 600
основной текст   16px / 400
подпись          13px / 400, --steel-400
```

Длина строки в текстах техники — до 70 символов.

### Чего не делаем

Не набираем подписи капслоком. Не выделяем одно слово в заголовке цветом. Не ставим
типографические ярлыки над каждым блоком. Не режем интерфейс на одинаковые скруглённые
карточки с одинаковой мягкой тенью. Не добавляем «→» в текст кнопок. Не используем
градиенты как украшение. Анимация появления блоков при скролле — не используется вообще;
движение только как ответ на действие пользователя.

Скругления разные по иерархии: крупные поверхности 12px, кнопки и чипы 8px, поля 6px.
Тени почти не используются — разделение через фон и границы.

## Экран тренировки

Самый важный экран продукта. Требования жёсткие, потому что им пользуются вспотевшей
рукой, с пола, одной рукой, иногда в перчатках, иногда на солнце.

```
┌─────────────────────────────────────┐
│ Жим гантелей лёжа        2 из 5     │  паттерн, позиция в сессии
├─────────────────────────────────────┤
│                                     │
│     16.0        ×        10         │  крупно, tabular-nums
│      кг                повторов     │  тап по числу → правка
│                                     │
│  ┌───────────────────────────────┐  │
│  │      Подход выполнен          │  │  основное действие, высота ≥56px
│  └───────────────────────────────┘  │
│                                     │
│  ✓ 16.0 × 10     ✓ 16.0 × 10        │  сделанные подходы
│  ○ подход 3      ○ подход 4         │
├─────────────────────────────────────┤
│  Отдых 1:28                         │  стартует сам, счёт от метки времени
├─────────────────────────────────────┤
│  Техника   Заменить   Осталось 15м  │
└─────────────────────────────────────┘
```

**Обязательное поведение:**

- Вес и повторы **предзаполнены** из прошлой тренировки с учётом прогрессии. Идеальный
  случай — подтверждение подхода в один тап, без ввода вообще.
- Таймер отдыха стартует автоматически после подтверждения подхода.
- **Таймер никогда не считает тики.** Хранится метка времени старта, оставшееся
  вычисляется как разница с текущим моментом. Иначе при сворачивании приложения на iOS
  таймер замерзает и показывает неправду.
- Экран не гаснет — Wake Lock API, с корректным переполучением блокировки после
  возврата из фона.
- Сигнал окончания отдыха — **звук через Web Audio**. Вибрация на iOS Safari не работает,
  на неё полагаться нельзя.
- Гифка техники разворачивается прямо здесь, не уводя с экрана.
- «Заменить» → альтернатива того же паттерна из доступного здесь и сейчас, с выбором
  причины.
- «Осталось 15 минут» → пересборка остатка сессии.
- Для односторонних упражнений — **раздельный лог левой и правой стороны**, с правилом
  симметрии.
- Уровень подсказок `verbose` даёт одно упражнение на экране с чек-листом техники;
  `quiet` — всю сессию списком с возможностью логировать не по порядку.

**Буфер подходов и устойчивость к связи.** Подтверждённый подход сразу попадает в Zustand
и отрисовывается — никаких спиннеров. Параллельно он кладётся в очередь и уходит на сервер
батчем с `client_uuid`, с экспоненциальными ретраями (1 с, 2 с, 4 с… до 30 с) и повтором при
возврате из фона и появлении сети. Индикатор синхронизации показывается только если очередь
не уходит дольше ~30 секунд. При закрытии вкладки с непустой очередью — предупреждение.

Буфер и момент начала отдыха хранятся в `localStorage` (`features/workout/queue.ts`): iOS
выгружает свёрнутую вкладку, и неотправленные подходы с таймером должны пережить это. При
открытии тренировки подходы с сервера объединяются с теми, что устройство ещё не отправило.
«Завершить» не срабатывает, пока в очереди есть подходы: закрытая тренировка их уже не примет.

**Как это устроено вокруг экрана** (`routes/_authed/workout.tsx`, `features/workout/`):

- Перед стартом — форма: что тренируем (следующий день программы или свободная тренировка),
  где (упражнения подстроятся под выбранное место) и три тапа самочувствия.
- Открытая тренировка подхватывается сама: `/workout` без параметров ведёт в неё, а не
  начинает новую.
- Пояснения движка (`notes_ru`) — над вводом подхода: последнее видно сразу и объявляется
  экранным дикторам, прежние — в раскрывающемся списке.
- На уличном месте, если прогноз плохой, — предложение перенести тренировку домой; в
  хорошую погоду блок прогноза на экране тренировки не показывается.
- Если в месте не осталось ни одного подходящего упражнения — понятный экран с
  «Завершить» и «Остановить», а не пустота.

## Прогресс и графики

Экраны `/progress`, `/progress/skills`, `/body`.

- Сводка недели: серия недель, тренировки и тоннаж крупными числами, рекорды «рядом».
- По движениям: две отдельные линии — ступень лестницы и лучший подход **текущей** ступени.
  Двух осей Y на одном графике нет никогда.
- Тоннаж по неделям: недели без тренировок остаются на оси с нулём — время не сжимается.
- Календарь месяца, рекорды, дисбаланс сторон с советом.
- Навыки сгруппированы: в работе / освоено / дальше; прогресс к цели и предусловиям,
  подводящие упражнения, ручная отметка для навыков без своего упражнения.
- Тело: вес линией среднего за 7 дней, обхваты, фото по ракурсам со сравнением «было / стало»
  шторкой; загрузка фото — прямо в хранилище по presigned-форме.

Правила графиков (`features/progress/charts.tsx`): одна серия на график, серия — цветом
текста, `--heat` — только на событиях прогрессии (новая ступень, рекорд) и с подписью в
подсказке, а не одним цветом; 2px линии, тонкая сетка, подсказка при наведении; у каждого
графика есть табличное представление.

## Погода

Уличному месту в разделе «Места» ставится отметка кнопкой «Я сейчас на этой площадке» —
геолокация телефона, координаты округляются до ~1 км ещё в браузере. Прогноз показывается
на карточке следующего дня программы, в форме старта и на экране тренировки; при плохой
погоде — кнопка сделать ту же тренировку дома. Решение предлагает, а не запрещает.

## PWA

Манифест, иконки (штанга из favicon: 192, 512, maskable, `apple-touch-icon`),
`display: standalone`, тема под цвет фона. На iOS установка только через Safari →
«Поделиться» → «На экран „Домой“»; в кабинете — короткая подсказка, как это сделать
(скрывается крестиком). На Android и в десктопном Chrome та же карточка показывает кнопку
«Установить приложение».

Service worker (`registerType: 'prompt'`) кеширует оболочку приложения. Новая версия не
перезагружает страницу сама — это могло бы случиться посреди подхода: появляется «Есть новая
версия», обновление по тапу. Данные пользователя через service worker не кешируются — этим
занимается TanStack Query; запросы к `/api` и `/progress-photos` в его кеш не попадают. Медиа
упражнений в справочнике пока нет — когда появятся, их кеширование добавляется отдельным
правилом.

## Доступность и качество

Видимый фокус на всех интерактивных элементах. Минимальная область нажатия 44×44.
Контраст текста не ниже 4.5:1. `prefers-reduced-motion` уважается — глобальный сброс
анимаций в `index.css`. Все формы работают с клавиатуры. Интерфейс не ломается при
системном увеличении шрифта. В раскладке есть ссылка «Перейти к содержанию». Таймер отдыха
не зачитывается экранным диктором каждую секунду — только «идёт отдых» и «отдых закончился».

## Тексты интерфейса

Русский, обращение на «ты», предложениями в обычном регистре. Кнопка называет действие:
«Начать тренировку», а не «Старт». Название действия не меняется по ходу сценария.

Ошибки объясняют, что случилось и что делать, без извинений и без размытых формулировок.
Пустые экраны — приглашение к действию, а не констатация пустоты. Формулировок,
играющих на чувстве вины за пропуски, нет нигде.
